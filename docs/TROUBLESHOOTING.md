# عیب‌یابی تانل اسپوف

هر مورد اینجا از یک خطای واقعی در راه‌اندازی گرفته شده است. اول به ترتیب چک کن.

---

## ۱) تانل پینگ می‌شود ولی ترافیک عبور نمی‌کند

**نشانه:** `ping 10.100.100.1` جواب می‌دهد و حتی اتصال TCP به پورت داخل تانل برقرار می‌شود، اما دانلود یا اتصال اینترنتی از داخل تانل تایم‌اوت می‌شود.

**علت رایج اول — سیاست `FORWARD` روی سرور خارج:**

```bash
iptables -S FORWARD | head -3
```

اگر `-P FORWARD DROP` دیدی و هیچ قاعدهٔ `tun0` نبود، ترافیک همین‌جا مرده است.

```bash
iptables -I FORWARD 1 -i tun0 -o $(ip -o -4 route show default | awk '{print $5;exit}') -j ACCEPT
iptables -I FORWARD 1 -i $(ip -o -4 route show default | awk '{print $5;exit}') -o tun0 \
  -m conntrack --ctstate RELATED,ESTABLISHED -j ACCEPT
```

**علت رایج دوم — نبودن `MASQUERADE`:**

```bash
iptables -t nat -S POSTROUTING | grep 10.100.100
```

اگر خالی بود:

```bash
iptables -t nat -A POSTROUTING -s 10.100.100.0/24 -o <IFACE> -j MASQUERADE
```

**علت سوم — `rp_filter`:** با IP جعلی، فیلتر مسیر معکوس بسته را می‌اندازد.

```bash
sysctl -w net.ipv4.conf.all.rp_filter=0
sysctl -w net.ipv4.conf.<IFACE>.rp_filter=0
sysctl -w net.ipv4.conf.tun0.rp_filter=0
```

اسکریپت `install.sh` هر سه مورد را انجام می‌دهد و در `spoof-tunnel-nat.service` ذخیره می‌کند تا بعد از ری‌بوت هم باقی بماند.

---

## ۲) بعد از ری‌بوت همه چیز قطع می‌شود

```bash
systemctl is-enabled spoof-tunnel spoof-tunnel-nat
```

باید `enabled` باشند. اگر نبودند:

```bash
systemctl enable --now spoof-tunnel spoof-tunnel-nat.service
```

نکته: اگر سرور یک ری‌بوت خورده باشد و تانل با نصب دستی (بدون اسکریپت) بالا آمده بود، همهٔ قواعد NAT هم پاک شده‌اند. با اسکریپت این اتفاق نمی‌افتد.

---

## ۳) سرویس بالا نمی‌آید

```bash
journalctl -u spoof-tunnel -n 50 --no-pager
```

| خطا | معنی | راه‌حل |
| :--- | :--- | :--- |
| `[FATAL] SIOCGIFHWADDR` | نام اینترفیس اشتباه | `--iface ens160` یا `ip -br a` برای دیدن نام درست |
| `bind: address already in use` | پورت UDP اشغال است | `--port` دیگری بده |
| فایل کانفیگ پیدا نمی‌شود | نصب بدون کانفیگ | `/etc/spoof-tunnel/config.yaml` را بساز، بعد نصب کن |

## ۳٫۵) بهترین کار: قبل از نصب تست کن

اگر نمی‌دانی اصلاً اسپوف روی این سرورها جواب می‌دهد یا نه، اول این را اجرا کن:

```bash
curl -fsSL https://raw.githubusercontent.com/lastdejavu/DEJ-SPOOF/main/scripts/spoof-test.py -o /tmp/spoof-test.py
# سرور اول:
sudo python3 /tmp/spoof-test.py listen --port 2390
# سرور دوم:
sudo python3 /tmp/spoof-test.py send --peer <IP_سرور_اول> --port 2390 --spoof 1.2.3.100
```

نتیجه مستقیماً می‌گوید اسپوف آزاد است، مبدأ بازنویسی می‌شود، یا بسته‌ها حذف می‌شوند — و نردبان اندازه هم فیلتر اندازه را نشان می‌دهد. با این تست، سه ساعت عیب‌یابی بعدی حذف می‌شود.

## ۴) افت شدید بسته داخل تانل

**نشانه:** پینگ `10.100.100.1` بین ۵۰ تا ۹۰ درصد بسته از دست می‌دهد و ترافیک سنگین رد نمی‌شود.

**علت:** مسیر بین‌الملل بسته‌های UDP بزرگ را حذف می‌کند (فیلتر اندازه).

**تست:**

```bash
# سرور خارج
python3 -c "import socket;s=socket.socket(socket.AF_INET,socket.SOCK_DGRAM);s.bind(('0.0.0.0',2380));[s.recvfrom(4096) for _ in range(60)]"

# سرور ایران
python3 - <<'EOF'
import socket, time
s = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
for size in (500, 800, 1000, 1200):
    for _ in range(15):
        s.sendto(b"X" * size, ("<IP_KHAREJ>", 2380))
        time.sleep(0.3)
EOF
```

**تفسیر:** اگر ۵۰۰ بایتی تقریباً کامل می‌رسد ولی ۱۲۰۰ بایتی نه، مسیر فیلتر اندازه دارد.

**راه‌حل‌ها به ترتیب:**

1. `--mtu 1360` سپس `1300` سپس `1200` (نصب مجدد با MTU جدید).
2. اگر MTU پایین هم جواب نداد، آن مسیر برای تانل **UDP** بسته است. دو گزینه داری:
   * یک واسط ثالث (سرور سوم) بین ایران و خارج بگذار.
   * برای این سرور از فوروارد TCP مستقیم استفاده کن (بدون تانل) — ساده‌تر ولی بدون جعل IP.

⚠️ آزمایش‌ها نشان داد کاهش MTU همیشه کمک نمی‌کند؛ چون خود قاب‌بندی تانل از سقف فیلتر بزرگ‌تر می‌ماند. اگر بعد از دو سطح کاهش جواب نگرفتی، وقت را بیشتر تلف نکن.

## ۵) پورت اینباند از بیرون باز نیست

```bash
# روی سرور ایران
iptables -t nat -S PREROUTING | grep <PORT>
ss -lntp | grep <PORT>        # نباید چیزی گوش بدهد، کار DNAT است
```

* قاعدهٔ DNAT باید به `10.100.100.1:<PORT>` اشاره کند.
* روی سرور خارج باید برنامه (xray/پنل) روی همان پورت listen کند: `ss -lntp | grep <PORT>`
* از یک شبکهٔ دیگر تست کن؛ از خود سرور ایران اتصال به IP عمومی خودش معمولاً کار نمی‌کند (hairpin NAT).

---

## ۵٫۵) ترافیک به تانل می‌رسد ولی برنامه جواب نمی‌دهد

اگر `nc -zv 10.100.100.1 9044` از سمت ایران جواب نمی‌دهد ولی `ping 10.100.100.1` سالم است:

**علت:** برنامه روی سرور خارج (xray / پنل) فقط به IP عمومی خودش گوش می‌دهد، نه به IP تانل.

```bash
# روی سرور خارج
ss -lntp | grep 9044
```

اگر آدرس `154.x.x.x:9044` بود و نه `*:9044` یا `0.0.0.0:9044`، ترافیک تانل (که به `10.100.100.1` می‌آید) به برنامه نمی‌رسد.

**راه‌حل‌ها:**

1. برنامه را روی `0.0.0.0` تنظیم کن (مثلاً در xray مقدار `"listen": "0.0.0.0"`).
2. یا ترافیک را NAT کن:

```bash
iptables -t nat -A PREROUTING -i tun0 -p tcp --dport 9044 -j DNAT --to-destination <IP_عمومی_سرور>:9044
iptables -t nat -A POSTROUTING -o tun0 -j MASQUERADE
```

⚠️ روش دوم با تانل اسپوف می‌تواند مسیر برگشت را بشکند؛ روش اول همیشه درست‌تر است.

## ۶) تست‌های درست

| هدف | تست | معیار قبولی |
| :--- | :--- | :--- |
| خود تانل | `ping -c 10 10.100.100.1` | ۰٪ افت |
| مسیر فوروارد | `nc -zv 10.100.100.1 9044` | متصل می‌شود |
| عبور واقعی داده | `verify.sh` (دانلود ۲۰ مگابایت) | HTTP 200 و سرعت معقول |
| اینباند عمومی | اتصال کلاینت واقعی از شبکهٔ ایران | هندشیک کامل |

نکته: `timeout 5 bash -c "</dev/tcp/IP/PORT"` از خود سرور به IP عمومی خودش نتیجهٔ گمراه‌کننده می‌دهد. همیشه از یک ماشین دیگر تست کن.
