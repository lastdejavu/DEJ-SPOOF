# تانل اسپوف ایران ↔ خارج (spoof-tunnel)

یک اسکریپت نصب ساده برای برقراری **تانل لایه ۳ با جعل IP مبدأ** بین یک سرور ایران و یک سرور خارج، و عبور دادن پورت اینباند پنل از داخل آن.

ساخته شده بر پایهٔ پروژهٔ [imanxboy/spoof-tunnel](https://github.com/imanxboy/spoof-tunnel).

> English: [README.en.md](README.en.md)

---

## این تانل چه کاری می‌کند؟

```
کاربر (v2rayNG)
      │
      ▼
┌──────────────────┐        UDP 2080 با مبدأ جعلی        ┌──────────────────┐
│  سرور ایران      │ ───────────────────────────────────► │  سرور خارج       │
│  10.100.100.2    │ ◄─────────────────────────────────── │  10.100.100.1    │
│  (client)        │                                      │  (server)        │
└──────────────────┘                                      └──────────────────┘
      │                                                            │
      └── DNAT پورت 9044 ───────────────────────► xray/پنل روی 9044 ┘
```

* ترافیک پورت اینباند (مثلاً `9044`) روی سرور ایران به داخل تانل فرستاده می‌شود.
* بسته‌های تانل با **IP مبدأ جعلی** ارسال می‌شوند، پس فیلترکردن IP واقعی سمت خارج کارساز نیست.
* سمت خارج بسته‌ها را می‌گیرد، NAT می‌کند و به برنامهٔ پنل (xray و…) تحویل می‌دهد.

## پیش‌نیازها

| مورد | مقدار |
| :--- | :--- |
| سرور ایران | Ubuntu 22.04 / 24.04 — دسترسی root |
| سرور خارج | Ubuntu 22.04 / 24.04 — دسترسی root |
| IP اضافی روی سرور خارج | برای جعل مبدأ (مثلاً `x.x.x.100` در همان ساب‌نت) — اختیاری ولی توصیه می‌شود |
| پورت UDP | یکی آزاد روی هر دو سرور (پیش‌فرض `2080`) |

## نصب سریع

### ۱) روی سرور خارج (kharej)

```bash
sudo ./scripts/install.sh --role server --peer <IP_IRAN>
```

### ۲) روی سرور ایران

```bash
sudo ./scripts/install.sh --role client --peer <IP_KHAREJ> --forward 9044,9033
```

همین. اسکریپت خودش اینترفیس شبکه را تشخیص می‌دهد، کانفیگ را می‌سازد، تانل را نصب می‌کند، قواعد فوروارد/NAT را می‌گذارد و در آخر تست می‌کند.

### ۳) تست

```bash
sudo ./scripts/verify.sh --peer-tun 10.100.100.1 --ports 9044,9033 --public-ip <IP_IRAN>
```

## گزینه‌های اسکریپت

| گزینه | توضیح | پیش‌فرض |
| :--- | :--- | :--- |
| `--role` | `server` (خارج) یا `client` (ایران) | اجباری |
| `--peer` | IP عمومی طرف مقابل | اجباری |
| `--spoof` | IP مبدئی که این سمت جعل می‌کند | سرور: `x.x.x.100` ساب‌نت خودش · ایران: IP واقعی خودش |
| `--peer-spoof` | IP مبدئی که طرف مقابل جعل می‌کند | IP واقعی طرف مقابل |
| `--port` | پورت UDP تانل | `2080` |
| `--forward` | پورت‌های اینباند (فقط سمت ایران) | — |
| `--mtu` | MTU تانل | `1440` |
| `--iface` | اینترفیس شبکه، اگر تشخیص خودکار غلط بود | خودکار |

مثال با MTU کمتر:

```bash
sudo ./scripts/install.sh --role client --peer 203.0.113.7 --forward 9044 --mtu 1300
```

## مدیریت روزمره

```bash
spoofctl status                 # وضعیت لحظه‌ای، سرعت، پکت‌لاس
journalctl -u spoof-tunnel -f   # لاگ زنده
systemctl restart spoof-tunnel  # ری‌استارت
ping -c 4 10.100.100.1          # تست پینگ داخل تانل (از سمت ایران)
spoofctl forward add 9033       # افزودن پورت
spoofctl forward del 9033       # حذف پورت
```

## عیب‌یابی

فایل کامل: [docs/TROUBLESHOOTING.md](docs/TROUBLESHOOTING.md)

خلاصهٔ مشکلات واقعی و پرتکرار:

| نشانه | علت | راه‌حل |
| :--- | :--- | :--- |
| تانل پینگ می‌شود ولی **هیچ ترافیک اینترنتی عبور نمی‌کند** | روی سرور خارج زنجیرهٔ `FORWARD` روی `DROP` است | `iptables -I FORWARD 1 -i tun0 -o <iface> -j ACCEPT` ← اسکریپت خودش انجام می‌دهد |
| همان مشکل، ولی `FORWARD` درست است | `MASQUERADE` برای شبکهٔ تانل وجود ندارد | `iptables -t nat -A POSTROUTING -s 10.100.100.0/24 -o <iface> -j MASQUERADE` |
| بعد از ری‌بوت همه چیز قطع می‌شود | سرویس `enabled` نبود | `systemctl enable spoof-tunnel` (اسکریپت انجام می‌دهد) |
| `[FATAL] SIOCGIFHWADDR` | نام اینترفیس اشتباه (`eth0` در برابر `ens160`) | `--iface` را درست بده |
| نصب با پیام خطا تمام می‌شود | `install.sh` اصلی بدون `/etc/spoof-tunnel/config.yaml` اجرا نمی‌شود | اسکریپت قبل از نصب کانفیگ را می‌سازد |
| پینگ داخل تانل ۵۰–۹۰٪ افت دارد و ترافیک سنگین رد نمی‌شود | مسیر بین‌الملل بسته‌های بزرگ UDP را می‌اندازد | `--mtu 1360` یا کمتر را امتحان کن؛ اگر جواب نداد **این مسیر برای تانل UDP مناسب نیست** (پایین را بخوان) |

### وقتی تانل UDP روی یک مسیر کار نمی‌کند

بعضی مسیرهای بین‌المللی بسته‌های UDP بالای یک اندازه را حذف می‌کنند. تست ساده:

```bash
# روی سرور خارج
python3 -c "import socket;s=socket.socket(socket.AF_INET,socket.SOCK_DGRAM);s.bind(('0.0.0.0',2380));
[s.recvfrom(4096) for _ in range(60)]" &
# روی سرور ایران
python3 - <<'EOF'
import socket,time
s=socket.socket(socket.AF_INET,socket.SOCK_DGRAM)
for size in (500,800,1000,1200):
    for i in range(15):
        s.sendto(b'X'*size, ("<IP_KHAREJ>",2380)); time.sleep(0.3)
EOF
```

اگر اندازه‌های بزرگ نرسیدند، کاهش MTU معمولاً کافی است. اگر نه، آن مسیر برای تانل UDP بسته است و باید مسیر دیگری انتخاب شود (مثلاً عبور از یک واسط ثالث یا فوروارد TCP).

## سؤال‌های متداول

**این تانل قابل شناسایی است؟**
IP مبدأ بسته‌های تانل جعلی است، پس بلاک کردن IP واقعی سرور خارج کارساز نیست. اما ترافیک همچنان UDP با الگوی مشخص است؛ اگر DPI فعالانه آن را بشناسد، ممکن است مشکل پیدا کند.

**مصرف پهنای باند چطور است؟**
هر بایت یک بار بین ایران و خارج رد و بدل می‌شود. اگر واسط میانی داشته باشید، دو بار.

**اگر کل اینترنت قطع شود کار می‌کند؟**
نه — این تانل به مسیر بین‌الملل نیاز دارد. برای قطعی کامل باید از مسیرهای داخلی/ترانزیت جایگزین استفاده کرد.

## امنیت

* روی سرورها از رمز قوی و ورود با کلید SSH استفاده کنید.
* پورت SSH و پورت تانل را در فایروال محدود کنید (تانل فقط به IP طرف مقابل نیاز دارد).
* این پروژه هیچ اعتبارنامه‌ای داخل خودش ندارد؛ همه چیز با آرگومان داده می‌شود.
